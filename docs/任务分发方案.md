# 任务分发与校验方案

## 一、先决条件：先有影印底本，再谈生成

**这是整个工程能否成立的关口。**

徐灵胎诸书虽是公有领域，但"公有领域"只解决版权问题，不解决**文本正确性**问题。任何语言模型都无法凭参数记忆逐字复现《难经经释》《兰台轨范》这类古籍；要求模型"生成原文"，必然出现**看起来通顺、实为杜撰**的句子，且比例不低。这与你"生成的内容一定不能有错"的目标直接冲突。

因此正确的形态不是"模型写古文"，而是：

```
影印底本 → OCR/录文 → 模型只做句读与讹字规范化 → 与影印件复核 → 入库
```

模型在其中只承担**标点与明显讹字**这一类低风险操作；原文词句一字不改。凡无线下影印件核对的内容，一律不得进入正式文本。

### 底本获取路径（建议）

| 书目 | 影印来源方向 |
| --- | --- |
| 1—6 种 | 乾隆半松斋原刻本（或可靠的民国以前影印本），国家图书馆/中华古籍资源库/高校馆藏 |
| 7—16 种 | 光绪刻本《徐灵胎医书十六种》 |
| 洄溪医案 | 咸丰七年蒋氏衍芬草堂刻本（王孟英校刊） |

已有公开扫描的资源站（如 archive.org、各类古籍数字库）可作起点，但需人工确认版本与卷次，**不得**用三十二种石印本。

## 三、按字数分片（子 agent 数量依据）

字数按常见传本粗估，用于**分片**，非精确统计。全稿约 **50—60 万字**，属长周期工程，必须分片并行。

| 分片 | 书目范围 | 粗估字数 |
| --- | --- | --- |
| W1 | 难经经释、神农本草经百种录、医贯砭 | 约 11 万 |
| W2 | 医学源流论、伤寒类方、慎疾刍言 | 约 12 万 |
| W3 | 兰台轨范 卷一—卷四 | 约 9 万 |
| W4 | 兰台轨范 卷五—卷八 | 约 9 万 |
| W5 | 洄溪医案、内经诠释、洄溪脉学、脉诀启悟注释、六经病解、舌鉴总论 | 约 10 万 |
| W6 | 伤寒约编、杂病源、女科医案 | 约 7 万 |

即：**6 个录入 worker + 1 个校验 worker + 1 个编排者**。

分片原则：按字数均衡而非按书目数量均衡；`兰台轨范`（8 卷、篇幅最大）独占两个分片；短小的身后汇刻十种合并成片，避免子 agent 空转。

## 四、Agent 角色

| 角色 | 职责 | 数量 |
| --- | --- | --- |
| 编排者（Orchestrator） | 分派单元、维护 `PROGRESS.md`、合并提交、卡关上报 | 1 |
| 取材 Agent | 定位并核对影印底本、截取/标注卷次页码 | 1 |
| 录入 Worker | 按分片完成 OCR 校对、句读、讹字规范化 | 6 |
| 校验 Agent | 抽取样本与影印件逐字比对，标出无依据的改动 | 1 |

## 五、编排循环

1. 取材 Agent 确认某书影印件版本与卷次，落盘到 `sources/`（不入正式库）。
2. 编排者把对应单元状态置为 `录入中`，指派给某一 worker。
3. Worker 完成一个单元后自检，更新台账为 `待校`，提交。
4. 校验 Agent 随机抽段与影印件比对，通过则置 `已校`，否则退回 `录入中`。
5. 编排者按需唤醒下一批单元，直到 36 个单元全部 `已校`。

## 六、卡关规则

- 影印模糊、缺页：标 `【缺】`，不得猜补。
- 版本冲突（如遇疑似别家伪书篇目）：立即上报，暂停该单元。
- 校验不通过率过高（某 worker 连续 2 个单元被退回）：停止该 worker，检查是否仍在凭记忆生成。
